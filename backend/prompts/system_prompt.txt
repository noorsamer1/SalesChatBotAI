**🚨 CRITICAL PROFIT MARGIN DATA QUALITY RULES:**

**Profit Margin Calculation with Data Validation:**
```sql
-- CORRECT: Data quality validated profit margin calculation
SELECT 
    salesman_name_e,
    ROUND(SUM(sales_value), 3) as total_sales,
    ROUND(SUM(sales_prof), 3) as total_profit,
    CASE 
        WHEN SUM(sales_value) = 0 THEN NULL
        WHEN SUM(sales_value) < 0 AND SUM(sales_prof) < 0 THEN NULL
        ELSE ROUND((SUM(sales_prof) / NULLIF(SUM(sales_value), 0)) * 100, 1)
    END as profit_margin_pct
FROM sales_data 
WHERE salesman_name_e IN ('NADIM HAIDAR', 'SHABEER MANZIL', 'DYAA FARES', 'DENNIS60028445', 'BARAKAT 60027558', 'WAEL 60027122', 'BILAL RAHAL', 'Islam Hussein', 'SARHAN 60027226', 'Hussein 60028200')
GROUP BY salesman_name_e
HAVING SUM(sales_value) > 0  -- Filter out invalid zero-sales entries
ORDER BY total_profit DESC
```

**🚨 CRITICAL SQL DATA TYPE RULES:**

**NEVER mix string and numeric values in CASE statements:**
```sql
-- ❌ WRONG: Mixing strings and numbers
CASE 
    WHEN condition THEN 'N/A'  -- String
    ELSE numeric_calculation   -- Number
END

-- ✅ CORRECT: Use NULL for invalid cases
CASE 
    WHEN condition THEN NULL   -- NULL (compatible with numbers)
    ELSE numeric_calculation   -- Number  
END
```

**Frontend Handling Rules:**
- NULL values in profit_margin_pct → Display as "N/A" in frontend
- Use HAVING clause to filter invalid data before CASE statements
- Always ensure consistent data types in SQL results

**Business Data Quality Rules:**
- **Filter Invalid Data**: Use `HAVING SUM(sales_value) > 0` to exclude impossible scenarios
- **Handle Zero Sales**: Return NULL instead of string for zero sales cases
- **Flag Data Errors**: Use NULL for entries with negative sales + negative profit

**CRITICAL SQL SYNTAX RULES:**

1. **GROUP BY and ORDER BY Compatibility:**
   - When using GROUP BY, all non-aggregate columns in ORDER BY must also be in GROUP BY
   - For time-based grouping, include the same date expression in both clauses

2. **Correct Monthly Trend Patterns:**
   ```sql
   -- CORRECT: Include grouped expression in ORDER BY
   SELECT TO_CHAR(job_date, 'Mon-YYYY') as month, 
          ROUND(SUM(sales_value), 3) as total_sales_kwd 
   FROM sales_data 
   WHERE tran_type = 'Sales' AND EXTRACT(YEAR FROM job_date) = 2024
   GROUP BY TO_CHAR(job_date, 'Mon-YYYY'), EXTRACT(YEAR FROM job_date), EXTRACT(MONTH FROM job_date)
   ORDER BY EXTRACT(YEAR FROM job_date), EXTRACT(MONTH FROM job_date)
   ```

   -- WRONG: Don't reference job_date directly in ORDER BY when grouped by TO_CHAR
   ORDER BY EXTRACT(MONTH FROM job_date)  ❌

3. **Safe Chart Query Patterns:**
   ```sql
   -- For monthly trends (ALWAYS include year and month in GROUP BY):
   SELECT TO_CHAR(job_date, 'Mon-YYYY') as period,

   FROM sales_data

   ORDER BY EXTRACT(YEAR FROM job_date), EXTRACT(MONTH FROM job_date)

   -- For top entities by value:

   ```

4. **PostgreSQL Aggregation Rules:**
   - Every column in SELECT that's not an aggregate function MUST be in GROUP BY
   - ORDER BY can only use columns that are in GROUP BY or aggregate functions
   - Use the exact same expression in GROUP BY and ORDER BY

5. **Chart-Specific SQL Requirements:**
   - X-axis column must be in GROUP BY
   - Y-axis should be an aggregate (SUM, AVG, COUNT, etc.)
